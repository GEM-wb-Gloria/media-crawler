## 1. 全名单 1432 家媒体的技术特点深度分析与分类

通过对《互联网新闻信息稿源单位名单》全部 1432 家媒体网站的实际网页结构、CMS 模版和内容形态进行全面遍历与技术审查，我们将其提炼为三大核心技术集群：

```text
国家网信办合规全量媒体 (1432家)
├── 集群 1: 主流新闻门户与专业报网 (743 家) ──── 通用新闻引擎 (media_crawler.py)
│    ├── 中央新闻网站和重点理论网站 (31 家)
│    ├── 中央新闻单位报刊网站 (67 家)
│    ├── 部委群团报刊网站 (117 家)
│    ├── 地方综合新闻网站 (511 家)
│    └── 其他单位报刊网站 (17 家)
│
├── 集群 2: 地方新闻单位 (573 家) ────────────── 报业广电引擎 (paper_and_broadcast_crawler.py)
│    ├── 地方报业传媒 (346 家，如北京日报、解放日报、广州日报等)
│    ├── 地方广播电视台网 (192 家，如各省市广播电视总台、北京时间等)
│    └── 地方融媒体中心 (35 家，县区融媒微门户)
│
└── 集群 3: 各级官方政务发布平台 (116 家) ──────── 国办标准政务引擎 (gov_platform_crawler.py)
     ├── 中央政务发布平台 (85 家，党中央各部委、国务院组成部门、直属机构等)
     └── 省级政务发布平台 (31 家，全国 31 个省/自治区/直辖市人民政府门户网)
```

### 1.1 主流新闻门户与专业报网 (743 家)
- **技术特点**：网站架构高度成熟，具备标准的时政、财经、科技、社会、国际等清晰栏目；页面多由静态或伪静态 HTML 呈现，URL 具有规律的日期层级（如 `/20260908/t20260908_xxxx.shtml`）；
- **解析难点**：各家 CMS 繁多，内嵌浮动广告、右侧推荐栏、相关阅读及换行脚本；
- **适配方案**：采用启发式正文块评分机制，结合 14 种主流正文容器选择器，全自动清洗广告与相关推荐，抽取出最纯净的事实段落。

### 1.2 地方报社传媒与广播电视台网 (573 家)
- **技术特点**：
  - **地方报业 (346 家)**：大量采用方正翔宇（Founder）、大汉版图等电子报/融媒采编系统，页面结构常使用 `#ozoom`, `td.font01`, `.news-content` 等固定容器；
  - **广播电视台网 (192 家)**：网页多为“音视频+文字实录”混合排版，常带有大型流媒体播放器标签、flash 占位符或主持人音频卡片；
  - **融媒体中心 (35 家)**：依托省级融媒云（如新华智云、天目云、赣云）生成的轻量门户；
- **适配方案**：在专用解析器中增加流媒体智能剥离模块（自动剔除 `<video>`, `<audio>`, `<iframe>`, `<embed>`, `<object>` 等标签），保留播报导语与新闻全文，并提取关键帧插图。

### 1.3 中央与省级政务发布平台 (116 家)
- **技术特点**：由中央部委（85 家）和 31 个省区市人民政府（31 家）构成。遵循国务院办公厅《政府网站发展指引》与政务公开技术规范；
- **特有要素**：除常规新闻标题和正文外，政务公文核心包含**“发文字号”**（如：国办发〔2026〕X号）、**“主题分类/索引号”**、**“成文日期/发布日期”**；正文容器高度规范化（多为 `#UCAP-CONTENT`, `#zoom`, `.pages_content`）；
- **适配方案**：建立全量权威官方域名映射库（`gov.cn`），自动将 PDF 中的中文别名解析为公网真实官方网址，并专项提取“发文字号”与“索引号”，提升公文证据力。

## 2. 系统技术架构与核心爬虫程序说明

为了避免单个脚本臃肿脆弱，同时给用户提供极简统一的操控体验，系统设计了模块化且高度集成的程序架构：

| 程序文件名 | 定位与覆盖范围 | 核心功能与特性 |
|---|---|---|
| **`media_crawler.py`** | **全网统一中央调度中枢**<br>*(支持全部 1432 家媒体)* | 1. **智能路由分流**：根据传入的媒体名称或分类，自动调度最适配的专用引擎；<br>2. 覆盖 743 家主流新闻网的多频道并发爬取；<br>3. 提供一键挂机爬取全网 1432 家媒体的批处理控制。 |
| **`paper_and_broadcast_crawler.py`** | **地方新闻单位专属引擎**<br>*(573 家报业/广电/融媒)* | 1. 深度适配方正电子报（#ozoom）与融媒体采编架构；<br>2. 自动剔除音视频流媒体噪音；<br>3. 严格分流存储至报业、广播电视、融媒体专属子目录。 |
| **`gov_platform_crawler.py`** | **各级政务发布平台专属引擎**<br>*(116 家中央部委与省政府网)* | 1. 内置 116 家中央部委与 31 省政府权威 `gov.cn` 域名库；<br>2. 国办标准模板解析（#UCAP-CONTENT）；<br>3. 自动抓取并结构化公文文号与政府索引号。 |
| **`sites_registry.py`** | **全量媒体配置中心** | 动态解析 `all_media_manifest.json`，提供媒体字典、权威域名补全、分类检索与过滤。 |
| **`all_media_manifest.json`** | **官方全量媒体档案库** | 1432 家媒体官方全景元数据（名称、官网、大类、细分子类标签）。 |

### 5.2 爬取单个指定媒体 (智能路由自动命中)

总程序 `media_crawler.py` 具有智能识别能力，输入任意媒体名称，系统会自动匹配并调用最优爬虫内核：

```bash

# 【案例 2：爬取地方综合新闻网】爬取新京报网或澎湃新闻
python3 media_crawler.py --site "新京报网" --max-per-site 20

python3 media_crawler.py --site "北京日报" --max-per-site 20

# 【案例 4：爬取地方广电台】爬取天津广播电视台（自动剔除视频流媒体噪音）
python3 media_crawler.py --site "天津广播电视台" --max-per-site 20

# 【案例 5：爬取中央部委政务平台】爬取中国政府网（自动提取发文字号和公文条款）
python3 media_crawler.py --site "中国政府网" --max-per-site 15

# 【案例 6：爬取省级人民政府门户】爬取北京市人民政府门户网站
```

```text
  --max-per-site N        每个媒体最多爬取的文章数量（默认 50，设为 0 表示不设上限）
```

## 7. 常见问题与技术保障机制

| 常见问题 | 原因分析与系统的自动处理方案 |
|---|---|
| **部分地方报刊或政务网址访问缓慢或超时** | 地方站点服务器带宽有限。系统设置了 10-12 秒超时，配备指数退避重试（重试 3 次）。若站点长期宕机，日志会以 `WARNING` 记录跳过，**绝不卡死主线程**，保障后续站点继续平稳运行。 |
| **有些地方小报出现中文乱码** | 许多老旧地方网站使用 `GB2312` 或 `GB18030` 编码且响应头未标注。系统内置自适应编码探测矩阵（`utf-8` -> `gb18030` -> `gbk` -> `gb2312`），多轮解码校验 `\ufffd` 替换符，确保正文 100% 正常显示。 |
| **政府网站的公文包含附件和表格** | 政务公文很多内嵌表格与条款序号。政务解析引擎对 `<p>` 和 `<div>` 进行分级保留，并自动过滤“扫一扫、公安备号、ICP”等底部页脚，提取发文字号和成文日期。 |
| **广播电视台只有视频没有大段文字** | 广电解析器专门剥离了 `<video>` 和播放插件，优先提取主持人播报文稿、新闻导语，如果文字少于 50 字则视为纯视频广播并予以剔除，确保事实核查语料的高纯度。 |
| **如何停止后台运行的爬虫进程？** | 执行 `pkill -f media_crawler.py` 即可优雅终止。已抓取的所有数据和 URL 会完整安全保存在本地。 |
